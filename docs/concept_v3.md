# KotoLang 構想メモ（第3版）

英語の聞き取りアプリ。個人開発、Android、オフライン専用。
このメモは、アイデアの壁打ち相手にそのまま渡せるように書いてあります。

第3版は、第2版で積み上がった矛盾の原因を潰した版。
原因はひとつ、**育成ゲームの数字に「学習の記録」を兼任させたこと**だった。
仕事を分けたことで、通貨・実・収穫・種まき・上限・買う飾りが全て不要になった。

---

## 1. 一行で

機械が訳せる時代に、訳さずに分かるための、聞き取り専用の育成アプリ。

---

## 2. なぜ作るのか

### 前提

AI によるリアルタイム翻訳は、遠からず実用水準に達する。
マニュアルを読む、メールを書く、案内を理解する。この用途で英語を学ぶ理由は、
これから急速に弱くなる。実用目的だけを掲げた英語学習アプリは存在理由を失う。

### それでも残るもの

翻訳が肩代わりできるのは「情報を受け取ること」で、代われないのは「その場にいること」。

- **間合い**。人の会話は、相手が言い終わる前に次を組み立てて始まる。その隙間はコンマ数秒。
  翻訳が挟まると必ず壊れる。遅延がゼロになっても壊れる。訳された言葉は本人の声ではない。
- **信頼の合図**。相手の言葉を話すことは、その相手に時間を投資した証明になる。
  翻訳が安くなるほど、自分で話せることの価値は上がる。
- **聞こえてくるもの**。翻訳は「向ける」必要がある。誰も頼まないから訳されない情報が大量にある。
  隣の席の雑談、会議の空気、通りすがりの一言。
- **端末が使えない場面**。騒がしい店、廊下での立ち話、急いでいるとき、電池切れ。
- **精度が要る場所**。翻訳は必ず何かを落とす。落ちるのは技術用語、法律、皮肉、含み。

### だから何を鍛えるか

**自然な速さで、初回で、文字なしで、会話についていく力。** これ一点。

読解も作文も語彙暗記もやらない。それらは機械が最初に食べる領域。

## 3. 三つの層と、それぞれの仕事

このアプリには三つの層がある。**層ごとに仕事を一つだけ与える。**
第2版が壊れたのは、育成の層に「測定」の仕事まで持たせたからだった。

| 層 | 仕事 | 持たせない仕事 |
|---|---|---|
| **難易度の梯子** | 学習の本体。測定と目標を担う | 楽しませること |
| **木と環境（育成）** | 明日も開かせること。それだけ | 上手さを証明すること |
| **記録画面** | 正直な事実を静かに置く | 演出、報酬 |

「継続」は語学で一番効く変数なので、育成の層に与えた仕事は十分に立派。
ただし**測定の仕事は絶対に持たせない**。持たせた瞬間に数字が嘘になる。

### 誰のために

- 英語を仕事や生活で「その場で」使う必要がある人。
- 教材として与えられた文章ではなく、自分の現実に近い場面で練習したい人。
- 買い切りで、広告も課金圧もない道具を求める人。

---

## 4. 制約（設計の前提として動かさない）

- **オフライン専用**。ネットワーク通信を一切しない。
- **権限ゼロ**。マイク、通知、位置情報、ストレージ、どれも要求しない。
- **アカウントなし**。ログインもクラウド同期もない。
- **AI の API キーをアプリに持たない**。生成はユーザー自身の AI にプロンプトをコピペし、
  返ってきた JSON を貼り付けて取り込む。
- **広告・分析・課金導線なし**。将来的には買い切り。
- **UI は10言語**。学習対象は常に英語。
- データは全て端末内。外に出るのは、ユーザー自身がコピーした文だけ。

この制約は不便ではなく特徴として扱う。「何も送らない」ことが売りになる。

## 5. 問題形式

原則：答えは「その場で実際にすること」であるべきで、時計を止めてはいけない。

### 一往復の流れ

```
返答の3択が出る → 読み終える → 相手の台詞が一度だけ流れる → 短い窓が開く → 返す
```

- **要旨の設問は廃止**。決断は往復ごとに1回だけ。
- **選択肢は台詞の前**。聞いた後に読む時間をなくし、純粋な聞き取りだけを残す。
- **正解は台詞側の一語で決まる**。返答は3つとも会話として自然で、どれも成立しうる。
  台詞の要となる一語（三時か四時か、行くのか行かないのか）を聞き分けたかで正解が決まる。
  読むだけでは絞れない。AI には「要の一語と紛らわしい対」を書かせる。
- **会話は止まらない**。窓を逃すと相手が言い直し、二度目の窓が開く。
  聞き逃したことが会話の中で分かる。
- **不正解に罰はない**。会話は進み、翌日と3日後の復習に入る。
  信号は「直近の正解率が下がり、次の段が遠のく」ことで足りる。
- ひとつの“会話”は2往復、一分を切る。

### 難しさは音に付ける

選択肢を難しくするのではなく、速度、雑音、訛り、声の重なりを上げる。
選択肢の難しさは読解の難しさであって、聞き取りの難しさではない。

### 往復の「型」 **[新規]**

UIも操作も変えない。選択肢を先に読み、音を一度聞き、返答を選ぶ。
変えるのは**何を捕まえないと正解できないか**。

一語の聞き分けだけを繰り返すと、飽きるだけでなく、
根幹が掲げた「会話についていく力」より**測定範囲が狭くなる**。
実際についていくには複数の別々の能力が要るので、往復に型を持たせて混ぜる。

| 型 | 台詞の例 | 試している力 |
|---|---|---|
| **一語で割れる** | "Can we push it to **four**?" | 音素の聞き分け |
| **反転語** | "I **can't** make it **unless** it ends early." | 否定・条件。聞き逃すと実害が最大 |
| **複数情報** | "North gate at three, not the main entrance." | 保持と照合。記憶負荷 |

**型は難易度の軸にしない。最初から混ぜる。**
型で解禁を作ると序盤が単調になり、飽き対策として機能しない。
また、難しさを問題の構造に置くことは「難しさは音に付ける」原則と衝突する。
難しさは速度と雑音が担当し、型は多様性だけを担当する。

**複数情報型は診断になる。** 選択肢を「時間が違う／場所が違う／両方合っている」で作れば、
誤答がそのまま「どの情報を取り落としたか」を示すので、復習で同じ弱点を突ける。

**採用しなかった型と、その理由**

- **含みを読む**（"Yeah... I mean, we *could* try that, I guess."）。
  根幹の「翻訳が落とすのは皮肉・含み」に直撃する型だが、**端末のTTSでは成立しない**。
  渋りは声の抑揚で伝わるもので、合成音声は抑揚がほぼ平板。
  オフライン・TTS前提という制約が構造的に排除している。
- **聞き逃しを補う**（途中が雑音で完全に潰れ、前後から推測して返す）。
  v1が気づいていた「聞き逃しても会話は続く」の直接的な実装だが、
  文脈で埋まるだけの冗長さを持つ台詞をAIに安定して書かせる必要がある。後の版で検討。

### 形式の揺らぎ **[新規]**

芯（選択肢を先に・台詞の一語で決まる・止まらない）は変えない。
だが**毎回まったく同じ**では、梯子が減速してくる後半に単調さが露出する。
芯を保ったまま、形を揺らす。

- **往復の数を揺らす。** 2往復固定をやめ、1往復の短いものから5往復の長いものまで混ぜる。
  実際の会話に長短があるのと同じ。長い会話には「後半まで集中が持つか」という別の負荷が生まれる。
  長さが読めないことは「残り数を見せない」原則とも噛み合う。
  決断は往復ごとに1回のままなので、決断の場所は増えない。
- **窓の長さを場面で変える。** 急いでいる相手との立ち話は窓が短く、のんびりした雑談は長い。
  第2章で挙げた価値の筆頭が「間合い」である以上、窓が常に一定なのはむしろ根幹に反する。
- **一本の中で音が変わる。** 静かな店内が途中から混んで騒がしくなる、電話の電波が悪くなる。
  一本の中に山ができるので単調さに直接効く。「難しさは音に付ける」の最も純粋な実装。
  音響パイプラインに手が入るので、実装は後続フェーズ。

選択肢の数は**3択で統一**する。読む時間は固定コストとして受け入れ、
テンポの変化は往復数と窓の長さで作る。

### 後から足すもの

新しい**場面タイプ**として、後の版で足す。どちらも今回は作らず、拡張点だけ残す。

- **自分宛てでない会話を聞く**。二人の話を横で聞き、何が決まったのかを拾う。
  翻訳を向けようと思いつかない領域なので代替されない。
- **答える対象を変える（行動を選ぶ）**。電話の自動音声で何番を押すか、
  駅のアナウンスを聞いてどのホームへ行くか。「答えは、その場で実際にすること」の直接的な形。

## 6. 難易度の梯子（＝学習の本体）

「細かいハードルを設けたアップグレード要素」は、ゲームの層ではなく**学習そのもの**として作る。
買うのではなく、**到達する**。

### 段の刻み方

| 軸 | 刻み | 段数 |
|---|---|---|
| 再生速度 | 1.00 → 1.05 → 1.10 → … | 約20段 |
| 雑音 | レベル1〜10 | 10段 |
| 訳の出方 | 直後 → 3秒後 → タップ時 → なし | 4段 |
| 訛り | 地域ごとに1つずつ | 地域数 |
| 聞き直し | 言い直しあり → 一度きり | 2段 |

合計で50段を超える。**一段ごとに、本当に上手くなっている。**

### 到達の条件

**直近 N 問をその設定で一定以上正解したとき、その段に到達したと認める。**

一度解けただけでは開かない。安定して取れて初めて次が見える。
これが「上手くなった証明」になる。

- 段は自由に下げられる。下げても記録は消えない（**最高到達段**を別に持つ）。
- 木は最高到達段で育つので、下げても縮まない。安心して負荷を探れる。
- 上げすぎて解けなくなったら下げる。自分にちょうどいい負荷を探す遊びになる。

### 上げる動機

通貨がないので「上げると得」はない。動機は二つだけ。

- **新しい場面が開く**（梯子の進行が唯一の解禁手段）
- **木が育つ**

上げることでしか進まないので、動機はこれで足りる。

### 「効率が良くなる」は事実として起きる

1.0倍・訳ありで40秒かかっていた会話が、1.4倍・雑音あり・一度きりでは25秒で終わる。
**同じ10分でこなせる量が実際に増える。**
倍率は演出ではなく事実。放置収入も指数関数も要らない。

### 長期の停滞感への対策：過去の自分に挑む **[新規]**

実力は本物である以上、必ず減速する。最初の1ヶ月で1.0倍→1.3倍まで進んでも、
1.3倍→1.4倍には数ヶ月かかる。これは正直な上達曲線の形であり、悪いことではない。
だが**数字が減速して見えると、育っている実感そのものが薄れる**リスクがある。

放置収入や変動報酬でこの減速を偽装することはしない（→11章）。代わりに、
**数字ではなく体験で実感を作る。**

- 数ヶ月前に苦戦した“会話”を、今の設定でもう一度聞かせる。
  当時は字幕なし・通常速度でも辛かったものが、今は雑音入り・高速でも普通に聞き取れる。
  これは計算された数字ではなく、事実としての対比。
- 何も偽装しない。測定でも報酬でもなく、「今の実力を過去との対比で見せる」だけなので、
  根幹とは矛盾しない。
- 発生のさせ方（アプリが差し込むか、記録画面から呼び出すか、節目で自動提案するか）は
  実装段階で詰める（→論点）。方向性だけ先に決めた。

減速そのものへの対処としては、パラメータ（速度・雑音）を上げ続けるのではなく、
**新しい種類の挑戦**（傍聴形式、電波の悪い電話、複数人の会話など）を時間を置いて
追加することも有効。「もう一段難しい」ではなく「新しい景色が開けた」という
質的な変化は、量を増やすより減速しにくい。

## 7. 木と環境（＝育成の層）

仕事は「明日も開かせること」だけ。測定はしない。

### 木の育ち方

**高さ ＝ 実力（最高到達段）／ 広さ ＝ 場面の数**

- 幹と高さは梯子の到達で伸びる。楽な設定で大量に解いても育たない。
- 枝の広がりは開いた場面の数で決まる。
- 両方伸ばした人の木が一番大きい。

### 環境の印

達成すると、木の周りに**自然物**が現れる。鳥、光、季節の変化など。

- **買えない**。買う飾りは存在しない（通貨がないので、そもそも作れない）。
- 何が現れたかは人によって違い、それが「自分だけの木」になる。
- 候補：音だけで全問正解 → 光る葉／最長コンボ → 鳥／連続日数 → 季節。

### 配置換え（庭師）**[新規]**

育成の層に「見るだけ」以外の手触りを足す。ただし測定にも解禁にも関わらせない。

- **物語**：自然に現れたものを、庭師のように手入れする。達成は自然が決めるが、
  どこに落ち着かせるかは自分で決める。「自然物なのに人が並べ替える」という
  違和感は、この一文で吸収する。
- **自由度は区画選択**。木の周りにいくつかの区画（スロット）があり、
  達成物をどの区画に置くかを選べる。座標を自由に指定する完全配置ではない。
  当たり判定や重なり処理を持ち込まず、実力に無関係な調整作業を増やさないため。
- **土台の広さは場面の数と連動**。新しい変数を増やさず、既存の「広さ＝場面数」を流用する。
  場面が増えるほど区画も増え、並べ替えの余地が広がる。
- 配置換えはいつでも自由に、何度でもできる。**正解にも記録にも一切影響しない。**
  やらなくても何も損しない（＝決断の場所にならない）。

### 画面構成

- **起動して一タップで音が始まる。** 聞く画面が中心。
- 木は聞いている間、背景に見えている。
- 木は**眺める場所**として全画面でも見られる。ただし**用事はない**。
  収穫も買い物も設定もそこにはないので、行かなくても何も損しない。
  だから「区切り」にならない。

## 8. 場面とコンテンツ

- 解禁の単位は**場面**（分野の中のシチュエーション）。
  「仕事」の中の「会議」「電話」「雑談」など。分野より細かい。
- 場面は**梯子の進行で開く**。通貨で買うのではない。
- 場面が開いたら、その場面の“会話”を AI に作らせる。
  この AI 往復は途切れではなく**解禁の儀式**として置く。
  「新しい場面が開く」が最大の報酬なので、その直後の往復は儀式になる。
- 頻度はユーザーのペース次第。往復の間、アプリ側では何も進まない。
- 内蔵の見本は新形式で作り直す。既存ユーザーのデータはリセットする。

## 9. 記録画面（＝測定の層）

演出なし。正直な事実だけを静かに置く。

- 現在の設定と、最高到達段。
- 各軸ごとの到達状況（速度はここまで、雑音はここまで）。
- 正答率、全期間と直近7日。
- 連続日数、最高記録、解いた“会話”数、音だけの連続、最長の連続正解。
- 直近28日のヒートマップ。
- “会話”の一覧。
- **経過時間の控えめな表示**。

## 10. 続けさせる仕掛け

「いつの間にかずっとやっていた」を作る。原因は具体的にある。

- **区切りをなくす**。決断の場所は、やめる場所。起動して一タップで音が始まる。
- **一決断一タップ**。「決定」と「次へ」の二段を廃し、タップで即確定、短い取り消し窓。
- **次を前の余韻に重ねる**。報酬の演出が終わる前に次の台詞を鳴らす。
- **残り数を見せない**。「1 / 2」と出ると人は2で止まる。
- **木を背景で育てる**。ごほうびを見に行かせない。
- **途中から正確に戻る**。“会話”の途中、台詞の途中まで含めて再開する。
- **開いたまま終わる**。やめる直前に次の“会話”の一行目を鳴らし始める。

第2版で入れた収穫・上限・モード切替は、いずれもこの原則を破っていたので削除した。

## 11. やらないこと

- **放置収入**。待つだけで増える数字は「分かった量」ではない。
- **通貨**。 **[第3版で削除]** 学習と無関係な買い物を招き、数字を二重にする。
- **収穫・種まき・実の上限**。 **[第3版で削除]** 全て「区切り」を作るだけだった。
- **買う飾り**。 **[第3版で削除]** 通貨がないので存在しえない。
- **変動報酬**。ランダムに大きな報酬が出る仕組みは、買い切りアプリでは搾取的に見える。
- **連続日数の喪失を煽る演出**。
- **数字が主役になること**。主役は木と「音だけで」の記録。
- **総合英語コース、単語帳、英作文の添削**。機械が最初に食べる領域。

ひとつ添えたいこと。これは滞在時間を伸ばす設計であり、
中身が本当に本人のためになっているときだけ正当化される。
「いつの間にか」が「気づいたら二時間」になったとき、
それを本人に伝えるアプリの方が、買い切りとして信用される。

## 12. 未解決の論点

### 梯子（最優先）

1. **梯子が多次元であること。** 速度・雑音・訳・訛り・聞き直しは独立に上げられる。
   到達判定を**軸ごとに独立**でやるか、**総合負荷スコア**を一つ作るか。
   独立だと分かりやすいが組み合わせが管理しづらい。総合だと「どれを上げても同じ」になり、
   苦手な軸を避けられてしまう。ここが第3版で一番大きな未解決。
2. **N の値と序盤のテンポ。** 直近N問で判定すると、最初の一段目が遠い。
   N を小さく（5問程度）し、序盤の刻みをさらに細かくする必要がある。
   「最初の“会話”を解き終わる前にひとつ目が開く」を守りたい。
3. **場面が開くペース。** 梯子の何段ごとに場面が開くか。
   序盤は密に、後半は疎に。ただし疎すぎると AI 生成の儀式が起きなくなる。

### 育成の層が薄すぎないか

4. **操作が消えた。** → **配置換え（庭師）を追加して解消済み。** 通貨も収穫も買い物もないので、
   一時は「育つのを見る」だけになっていたが、達成物を区画に並べ替える操作を足した。
   測定にも解禁にも関わらないので、根幹とは矛盾しない。手応えとして十分かは実装後に確認したい。
5. **達成の自然物の設計。** 何を達成すると何が現れるか。数と種類。区画の数と、達成物の数の釣り合い。
6. **転生（プレステージ）。** 通貨経済のための仕組みだったので、いったん消えた。
   梯子を登り切った後に何を置くか、そもそも置くかは未定。
7. **「過去の自分に挑む」の発生トリガー。** アプリが時々予告なく差し込むか、
   記録画面から自分で呼び出せるか、月次などの節目で自動提案するか。方向性のみ決定済み。
8. **新しい種類の挑戦の追加ペース。** 傍聴形式などの新形式を、どのくらいの間隔で
   長期ユーザーに提示するか。

### 問題形式

7. **言い直しと「一度しか聞けない」の衝突。** 言い直しは二度目の再生なので、
   この段に到達した人には矛盾する。言い直しを「少し違う言い方」にすれば両立するが、
   AI 生成の負担が増える。
8. **三つの自然文を先に読ませる記憶負荷。** 読解時間が消えたのではなく、
   前に移って記憶負荷に化けていないか。選択肢が短く並行しているほどこの形式は効く。
9. **「台詞側の一語で決まる」生成の安定性。** AI に「3つとも自然で、
   台詞の一語だけで正解が決まる」返答を書かせられるか。JSON にどう持たせるか。
10. **傍聴形式の拡張点。** 後から足すと決めたが、
    今のうちに場面タイプの拡張点だけは残しておくべきか。

### その他

11. **将来のマネタイズ。** 買い切りの価格、無料で試せる範囲、内蔵見本の量。

## 13. 判断の物差し

迷ったときはこれで決める。

- **機械が代われる能力を鍛えていないか。** 読解や翻訳の練習になっていたら方向が違う。
- **その数字は本当に理解した記録か。** 待つだけで増えるなら嘘になる。
- **その層に、二つの仕事をさせていないか。** **[第3版で追加]**
  報酬でありながら記録でもある数字を作った瞬間、必ずどちらかが嘘になる。
- **決断の場所を増やしていないか。** 決断の場所は、やめる場所。
- **買うと楽になっていないか。** そもそも買うものがない。到達するだけ。
- **端末の外に何か出ていないか。** 出るのはユーザーがコピーした文だけ。

## 付録：第2版から捨てたもの

| 捨てたもの | 理由 |
|---|---|
| 通貨（お金） | 学習と無関係な買い物を招く。梯子が解禁を担えば不要 |
| 実 | 「記録」と「報酬」を兼任して壊れた。記録は記録画面へ |
| 収穫（手動） | 聞くのをやめさせる区切りだった |
| 実の上限 | 調子が出た瞬間に強制中断させる。最悪の区切り |
| 種まき | 収穫だけで足り、操作が増えるだけだった |
| コンボの報酬効果 | 罰が指数的に育ち、「やめ時」を作っていた（記録には残す） |
| 木の段階の掛け算倍率 | 作業量で指数が伸びるので、実力の記録にならなかった |
| 二つのモード | モード切替そのものが最大の区切りだった |
| 買う飾り（人工物） | 通貨がないので存在しえない。環境は達成の自然物だけ |
| 難易度を鍵として買う | 買うのではなく到達する形に変えた |
