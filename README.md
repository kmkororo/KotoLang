# KotoLang — Flutter (Android + iOS)

*Your world. Your English.*

An English listening app whose material is generated by **your own AI**, not by
a server this app pays for. You copy a prompt into ChatGPT / Claude / Gemini,
paste the reply back, and KotoLang turns it into questions on your device.

There is no AI API in this app, no backend, no login, no analytics and no ads.

## Architecture

```
UI (features/)          Riverpod providers, Material 3 widgets
   ↓
Repository (data/)      imports, session planning, resets, backup
   ↓
Domain (domain/)        SRS, scoring, question generation — pure Dart, no I/O
   ↓
Drift (data/database)   SQLite
```

The domain layer has no Flutter or database imports at all, which is why it can
be tested exhaustively without a device.

| Choice | Why |
|---|---|
| **Riverpod** | Providers are overridable, so tests run the real widgets against an in-memory database. |
| **Drift / SQLite** | The data grows and is relational; Drift gives typed queries, indexes and an explicit migration path. The only backup is the user's own export, so schema evolution has to be deliberate. |
| **Map-based i18n** | Ten languages, one screen family. A plain map is auditable and needs no codegen; a test asserts every locale defines every key. |
| **JSON columns for list fields** | Option arrays and id lists are always read and written whole, never queried across. Join tables would add schema surface and buy nothing. |

## Interface language vs learning language

The language you **read** is separate from the language you **learn**.

- Learning language: English (fixed).
- Interface language: chosen on the very first screen, changeable any time in
  Settings → Interface.

Supported: 🇯🇵 日本語 · 🇺🇸 English · 🇪🇸 Español · 🇧🇷 Português (Brasil) ·
🇫🇷 Français · 🇩🇪 Deutsch · 🇰🇷 한국어 · 🇨🇳 简体中文 · 🇮🇳 हिन्दी ·
🇮🇩 Bahasa Indonesia

The choice goes further than labels: the AI prompts name the language
explicitly, so translations, meanings and distractors are generated in it.
Material already imported keeps the translations it was created with — Settings
says so rather than pretending otherwise.

## Question formats

| Format | What it asks | Options |
|---|---|---|
| Paraphrase | Which English sentence means the same? | 4 English sentences |
| Meaning | Which reading matches what you heard? | 4 in your language |
| Dictation | Build the target expression | tap word tiles |
| Word order | Rebuild the sentence | tap word tiles |

The first two are weighted to roughly 60% of the mix. Their wrong options differ
from the answer by exactly one thing — negation, who acts, tense, a condition,
or strength — so they cannot be solved without hearing the detail.

Everything is answered by tapping. Dictation offers a keyboard, but never as the
default: typing English on a phone is the friction most likely to end a session.

## Learning model

- **Spaced repetition** on the *expression*, not the question: `1 → 3 → 7 → 16 →
  35 days`, back to tomorrow on a miss.
- **Recognition gate.** Multiple choice alone caps an item at box 3. It only
  advances further after a correct dictation or word-order answer, so "I tapped
  the right button" never counts as mastery.
- **Selection order**: due reviews → weak items → *never-studied* → everything
  else by staleness. New material ranking above seen-but-not-due is what keeps
  sessions varied; without it the planner drills a handful of items forever.
- **One question is a full day.** A study day is any day with at least one
  answer. Correctness is irrelevant — attempting something hard and missing it
  still counts as showing up.
- **Streak freezes** cover missed days automatically. When they run out the
  streak ends without reproach, and the best streak is kept.

## Data, privacy and backup

Everything lives in SQLite on the device. This app performs **no network
requests at all** — there is no code path that sends learning data anywhere.
What you type into an AI is governed by that service's own policy.

Because there is no cloud copy, **Export is a real feature, not a nicety**:
Settings → Data → Export writes a JSON file you keep. Import merges it back.

Resets are scoped so replacing material never costs you your record:

| Action | Removes | Keeps |
|---|---|---|
| Delete this area's material | its expressions, sentences, questions, schedules | the area itself, other areas, your record |
| Delete the area as well | the above plus the area | other areas, your record |
| Delete all material | every expression, sentence, question, schedule | areas, streak, XP, history |
| Reset my record only | schedules, history, streak, XP | all material |
| Clear profile and areas | profile, areas, material | streak, XP, history, settings |
| Erase everything | everything | your chosen language only |

Each one shows the exact counts before it removes anything. An expression shared
by two areas is unlinked, not deleted.

## Testing

`flutter test` — **74 tests**, all passing.

| Suite | Covers |
|---|---|
| `domain_test.dart` (32) | SRS intervals, recognition gate, format rotation, streak & freeze arithmetic, XP bounds, question generation and grading, DST-safe dates |
| `l10n_test.dart` (9) | every locale defines every key, no unused keys, placeholders consistent, device-locale resolution |
| `repository_test.dart` (25) | imports persist, malformed replies never throw, breadth-first introduction, no repeated sentences, scoped resets, export/restore round trip |
| `app_flow_test.dart` (8) | real widgets over a real database: first-run language picker, onboarding routing, answering a question, switching interface language |

Two real defects were found by these tests and fixed:

1. **Infinite rebuild loop** — the shell assigned a fresh settings object from a
   frame callback every build, which notified, rebuilt and reassigned. State is
   now derived from the boot provider instead.
2. **Crash on leaving a session** — `QuizScreen.dispose()` used `ref` after
   disposal. The speech service is now captured in `initState`.

A third was found while wiring startup: awaiting the TTS engine could hold the
app on its splash forever. Speech now warms up without blocking, with a timeout.

### Signing — action required

The current artifacts are **signed with debug keys** and Play will reject them.
To produce an uploadable build:

```bash
keytool -genkey -v -keystore %USERPROFILE%\kotolang-upload.jks \
  -storetype JKS -keyalg RSA -keysize 2048 -validity 10000 -alias upload
```

Then create `app/android/key.properties` (git-ignored, never commit it):

```properties
storePassword=<your password>
keyPassword=<your password>
keyAlias=upload
storeFile=C:/Users/kmkor/kotolang-upload.jks
```

`flutter build appbundle --release` then signs with it automatically. **Keep
that keystore and its passwords safe — losing them means losing the ability to
update the app.** Enrol in Play App Signing so Google holds the app key.

The artwork is a rounded badge occupying 71% of its canvas, slightly wider than

### Why `ios/` lives inside `app/`

The requested path was `…\KotoLang\ios`, and an empty folder is there. A Flutter
iOS target cannot live detached from its project: `ios/` must sit beside `lib/`
and `pubspec.yaml` so the build can find the Dart code, the plugin registrant
and the generated config. The working target is therefore `app/ios/`. The empty
folder can be deleted.

### On a Mac

```bash
# Copy the project across, then:
cd KotoLang/app
flutter pub get
cd ios && pod install && cd ..

flutter run -d <device>              # simulator or a tethered iPhone
flutter build ipa --release          # App Store archive
```

`pod install` matters: CocoaPods dependencies are resolved on macOS only, so
`ios/Podfile.lock` does not exist yet and cannot be generated here.

### Expected to need attention on the Mac

- **Text-to-speech.** `flutter_tts` uses AVSpeechSynthesizer on iOS, a different
  engine from Android's. Voice names and quality differ, so the voice picker and
  the ranking in `lib/core/speech.dart` should be re-checked on a real device.
- **SQLite.** `package:sqlite3` 3.x supplies its own native build.
  `sqlite3_flutter_libs` is now an intentional no-op shim kept only to prevent
  the old build scripts from being used. This works on Android (verified); the
  iOS path is the same mechanism but is unverified.
- **Signing.** An Apple Developer account, a bundle ID registered on the
  developer portal, and a provisioning profile are required before any build
  can run on hardware.
- **Privacy manifest.** Recent App Store submissions require
  `PrivacyInfo.xcprivacy` declaring required-reason API usage. KotoLang collects
  nothing, but the file still has to exist and declare the file-timestamp and
  user-defaults APIs its dependencies use.
